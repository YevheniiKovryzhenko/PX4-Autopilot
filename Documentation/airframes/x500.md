# Holybro X500 V2 — Simulink development variants

## Build and select

```sh
make cubepilot_cubeorangeplus_simulink -j4
# Or, for a deployed model that owns control and mixing:
make cubepilot_cubeorangeplus_simulinkctrl -j4
```

Use `cubepilot_cubeorange` or `px4_fmu-v6c` for their corresponding hardware. Upload the selected build's `.px4` package through QGroundControl’s **Custom Firmware** option. Fully close and restart QGC to see the new airframes, then select the matching X500 preset and apply/reboot the flight controller:

| Preset | ID | Intended startup |
| --- | ---: | --- |
| Holybro X500 V2 - Simulink Guidance | 4030 | Mode 1: stock quadrotor control plus Simulink tasks |
| Holybro X500 V2 - Simulink Full Control | 4031 | Mode 2: generated controller publishes motor/servo demands directly |

Both are custom airframes with their own quad-X geometry; Guidance 4030 retains the stock X500 tuning without depending on a packaged stock airframe. Enabling custom airframes packages both presets. Choose Guidance for a full build in mode 1 and Full Control for a minimal build in mode 2. The airframe does not force the saved `SIMULINK_MODE` value. See the module README for common setup, build flags and parameter precedence.

## Outputs and guidance

Motor 1–4 identify the standard quad-X flight motors. These airframes do not assign physical PWM or CAN connectors; map the logical functions to the actual output ports in QGroundControl. Servo functions are available for model-defined peripherals. On Cube hardware, MAIN uses PX4IO and AUX uses the FMU PWM output driver.

For mode 1, ensure the guidance output includes the topic consumed by stock control or the intended model. For mode 2, deploy the generated controller and verify that it owns `actuator_motors`/`actuator_servos`. Guidance alone does not implement the flight controller. Hardware trajectories use `/fs/microsd/Trajectories/`; saved `SMG_TRAJ_DIR` values take precedence.

## Simulation

The existing S500 surrogate targets are separate simulation airframes:

```sh
make px4_sitl_simulink gz_s500_simulink
make px4_sitl_simulinkctrl gz_s500_simulink
```

Use the launch targets present in the selected branch; v1.16.1 does not currently contain the `gz_s500_simulinkctrl` wrapper, so use a compatible simulation airframe with its mode-2 build. The S500 model is not a physical X500 calibration. Lidar variants are simulation options and do not configure real CAN sensors.
