# S2F-X200 — external-control VTOL

## Build and select

```sh
make cubepilot_cubeorangeplus_simulinkctrl -j4
```

Upload `build/cubepilot_cubeorangeplus_simulinkctrl/cubepilot_cubeorangeplus_simulinkctrl.px4` through QGroundControl’s **Custom Firmware** option. Fully close and restart QGC to see the new airframes, then select **S2F-X200** in the Standard VTOL group (ID **22000**) and apply/reboot the flight controller. The intended external-control configuration is `SIMULINK_MODE=2`; verify the saved value. Cube Orange and FMU v6c also have `simulinkctrl` profiles. Builds do not automatically select the airframe.

The generated model supplies flight control and allocation. Stock VTOL defaults provide vehicle classification and supporting parameters; the preset's actuator metadata is not a tuned stock allocation matrix. Mode-1 builds retain stock controllers but this external-control preset must not be assumed to provide a validated stock X200 control configuration. See [common setup](../../src/modules/simulink_parameters/README.md) for startup, shared disarming defaults, telemetry and tooling.

## Logical actuator mapping

Physical PWM/CAN routing is intentionally unassigned on hardware. Select the Motor/Servo functions on the actual outputs in QGroundControl.

| Function | Component |
| --- | --- |
| Motor 1–4 | VTOL lift motors |
| Motor 5 | Cruise motor |
| Servo 1 | Left outboard aileron |
| Servo 2 | Left flap |
| Servo 3 | Right flap |
| Servo 4 | Right outboard aileron |
| Servo 5 | Left elevator |
| Servo 6 | Right elevator |
| Servo 7 | Rudder / reserved model slot |

This order follows the existing X200 model interface. Match it to the deployed model before connecting actuators. Project-specific stick mapping, state transitions and tuning remain in the project model and its own documentation. Hardware trajectories are read from `/fs/microsd/Trajectories/`.

## Simulation

```sh
make px4_sitl_simulinkctrl gz_s2f_x200
```

The pinned experimental Gazebo model uses airframe **22001** and inherits the shared X200 hardware presets, then selects simulator output mappings and local trajectories. Its five ESC channels use the model's 838 rad/s upper endpoint; seven servo channels use ±30° limits. These simulator mappings are not physical hardware routing. The separate **22000** POSIX wrapper supports an external simulator and maps five motors followed by seven servos to virtual outputs. Simulation trajectories use the launch working directory's `Trajectories/` folder.
